# 实验报告：Phase 2 — 视觉感知模块

**日期**: 2026-05-19 ~ 2026-05-20

---

## 一、阶段目标

在 Phase 1 搭建好场景控制和数据采集基础设施之后，这个阶段要完成机器人对室内环境的视觉感知能力。具体来说：

1. 用 YOLOv8 对 AI2-THOR 渲染画面做物体检测，输出物体名称、边界框、屏幕位置
2. 对检测到的物体估计距离（近/中/远）
3. 针对 YOLO 在仿真画面上检测效果差的问题，搭建微调工具链
4. 将类别配置从硬编码改为 YAML 可配置
5. 用量化指标评估检测质量，建立微调前后的对比基线

---

## 二、模块设计

### 2.1 检测器 (detector.py)

`YOLODetector` 封装了 ultralytics 的 YOLO 模型。输入 RGB 图像，返回 `Detection` 列表，每条包含标签名、置信度、边界框和自动计算的屏幕位置（left/center/right）。

YOLO 的 COCO 80 类里没有 door、cabinet、lightswitch 等室内常见物体。这个限制在后面通过可配置类别系统和微调来解决。

此外支持了非极大值抑制（NMS）的 IOU 阈值调节，以及 5 种不同规模的预训练模型（yolov8n/s/m/l/x）。

### 2.2 距离估计 (depth.py)

两个策略：`HeuristicDepth` 用边界框面积占画面比例来划分 NEAR（>15%）、MEDIUM（>5%）、FAR（其余），纯几何经验公式，不需要 GPU。`DepthAnythingV2` 用单体深度估计模型，精度更高但需要额外依赖和 GPU。

目前验证集上的实验都用启发式方法，速度无感知差异，后续如果需要更精确的深度信息可以切换到 Depth Anything。

### 2.3 CLIP 验证器 (verifier.py)

YOLO 的检测精度在 AI2-THOR 画面里偏低（mAP@0.5 只有 0.14 左右），很多检测结果是错误的。CLIP 验证器对每个 YOLO 检测框的裁剪区域计算文本-图像相似度，可以作为第二层过滤。实验中发现，用 CLIP 对 "a photo of a {label}" 做验证，可以把一些明显标错的框过滤掉。

不过 CLIP 在 CPU 上速度太慢（每帧几秒），目前只在手动 demo 里作为可选的增强功能。

### 2.4 场景先验 (prior.py)

根据 AI2-THOR 的 FloorPlan 名称判断房间类型（厨房/卧室/浴室/客厅），对检测到的物体做置信度加权。比如在厨房里 refrigerator 的置信度 ×1.3，bed 的置信度 ×0.5。这个模块只调权重不下结论，是否过滤留给下游决定。

实际效果有限——因为 YOLO 本身的检测太差，权重调整改变不了漏检的问题。但在后续微调后，先验可以在边缘情况下帮助区分疑似类别。

### 2.5 类别配置系统 (class_config.py + classes.yaml)

这是解决 YOLO COCO 类别限制的关键设计。所有的类别名和 AI2-THOR 物体类型到类别名的映射都在 `config/classes.yaml` 这一个文件里。加新类（比如 door、cabinet）只需：

```yaml
names:
  - ... (原有 80 个 COCO 类)
  - door          # 加这里

thor_to_names:
  Door: door      # 加这里
```

不需要改任何 Python 代码。三个下游模块——检测器、数据采集、评估——都从同一个配置加载，保证一致性。

辅助命令 `python src/cli/perceive.py --check-classes` 加载一个场景，列出所有 AI2-THOR 物体，标注哪些已映射到 YOLO 类别、哪些还没，直接给出需要添加到 yaml 的行。

### 2.6 数据采集与标注 (finetune/collect.py)

利用 AI2-THOR 的实例分割功能自动生成训练数据。原理是：开启 `renderInstanceSegmentation` 后，AI2-THOR 返回一张颜色掩码图——每个可见物体一个独有颜色。通过 `color_to_object_id` 映射查到物体类型，再从掩码像素坐标算出边界框，写入 YOLO 格式的标签文件。

这个过程完全不需要人工标注，标签质量由 AI2-THOR 保证（像素级精确）。机器人在场景中随机走动，自动采集帧和标签对。

目前支持设置可视距离到 10 米（覆盖整个房间），避免了之前默认 1.5 米只看到近处物体的问题。

### 2.7 评估模块 (finetune/eval.py)

评估流程分为两步：先在 AI2-THOR 中自动生成验证集（默认用训练集以外的 FloorPlan11-15），再用 ultralytics 的 `model.val()` 计算 mAP@0.5、mAP@0.5:0.95、Precision、Recall。

评估时会自动检测模型的类别数——预训练模型只评估 80 个 COCO 类（跳过自定义类），微调后模型评估全部类别。

输出包含整体指标表格和每个类的 GT（ground-truth 标注数量）、AP@0.5、状态标签。状态分为四档：

- GOOD：AP≥0.6，可靠检测
- OK：AP≥0.3，可用，微调可提升
- LOW：AP>0，差，需要微调或更多数据
- NONE：AP=0，完全检测不到

### 2.8 可视化验证 (--verify-labels)

`python src/cli/perceive.py --verify-labels` 提供标注质量的可视化检查。机器人在场景中做 360° 环绕扫描→前进→再扫描的探索模式，每帧把 AI2-THOR 的 ground-truth 边界框和类别名画在图像上，保存到 `outputs/verify/`。

运行结束后输出覆盖率报告，分两类：被标注至少一次的物体、从未被标注的物体（附原因分析）。这个功能在调类别映射时非常有用——可以直观看到哪些物体在实例分割中有框、哪些没有。

## 三、评估结果（微调前基线）

用 yolov8n.pt（预训练权重，未微调）在 FloorPlan11-15（5 个场景，398 帧，1454 个标注框）上评估：

### 3.1 整体指标

| 指标 | 数值 |
|------|------|
| mAP@0.5 | 0.1462 |
| mAP@0.5:0.95 | 0.1125 |
| Precision | 0.4729 |
| Recall | 0.1524 |

### 3.2 各类表现

| 类别 | GT 数量 | AP@0.5 | 状态 |
|------|---------|--------|------|
| microwave | 133 | 0.4740 | OK |
| sink | 141 | 0.3327 | OK |
| refrigerator | 207 | 0.2159 | LOW |
| toaster | 151 | 0.1549 | LOW |
| dining table | 75 | 0.1316 | LOW |
| cup | 98 | 0.0464 | LOW |
| apple | 47 | 0.0405 | LOW |
| bowl | 59 | 0.0376 | LOW |
| chair | 34 | 0.0284 | LOW |
| oven | 549 | 0.0000 | LOW |
| fork | 46 | 0.0000 | NONE |
| knife | 71 | 0.0000 | NONE |
| spoon | 35 | 0.0000 | NONE |

验证集中总共标注了 13 个类别（COCO 80 类中只有这些出现在 AI2-THOR 室内场景里）。

    Status legend:
      GOOD  AP>=0.6  — reliable detection
      OK    AP>=0.3  — usable, fine-tuning will improve
      LOW   AP>0     — poor, needs fine-tuning or more data
      NONE  AP=0     — never detected (not in COCO / no samples)

### 3.3 分析

预训练 YOLO 在 AI2-THOR 渲染画面上整体表现差（mAP@0.5=0.14）。这和预期一致——YOLO 是在真实照片上训练的，AI2-THOR 的 Unity 渲染画面在纹理、光照、材质上和真实照片有本质差异。

表现最好的两个类是 microwave（AP=0.47）和 sink（AP=0.33），猜测是因为它们的几何形状比较规整、纹理特征在仿真中保留得较好。表现最差的是 fork、knife、spoon 这些小物件（AP=0），它们在画面中占比太小，预训练模型完全检测不到。

oven 有 549 个标注但 AP 只有 0.0000——这个数字说明 YOLO 对烤箱有一些检测但置信度太低，被 NMS 过滤掉了。

## 四、开发中遇到的问题

### 4.1 AI2-THOR 默认可视距离过短

在第一次跑 `--verify-labels` 时，发现大量物体没有标注框。排查后发现 AI2-THOR 的默认 `visibilityDistance=1.5m`，实例分割只渲染 1.5 米内的物体。室内场景通常 5-10 米见方，大部分物体都在这个范围外。修复方式是把验证和采集时的可视距离设置为 10 米。

### 4.2 YOLO 类别数与标注类别数不匹配

评估时遇到了 `IndexError: index 83 is out of bounds for axis 1 with size 81`。原因是 `classes.yaml` 里加了自定义类后总共有 131 个类别，但预训练 YOLO 只支持 80 个 COCO 类。生成的验证集标注里包含了 class_id>79 的标签。修复方式是在采集验证集时自动检测模型的类别数，过滤掉超出范围的标签。

### 4.3 AP 数组与类名索引对应错误

评估表格一直不输出数据，排查后发现是从 YOLO 的 `metrics.box.ap` 取值时，默认按数组下标对应类名，但 YOLO 的 AP 数组只包含有 GT 标注的类，下标和 class_id 不一致。需要用 `metrics.box.ap_class_index` 来做正确的类名映射。

### 4.4 部分物体在实例分割中不可见

即使映射配置正确、可视距离足够，有一部分物体（如小厨具 Bottle、Fork、Lettuce）仍然在验证阶段没有被标注到。原因是它们在 AI2-THOR 场景中被放在了柜子、抽屉里，物理上不可见。这不影响训练——YOLO 不需要标注看不见的物体。

另外一些结构物件（如 Door、Window）可能在某些 AI2-THOR 场景中根本不存在，或者 AI2-THOR 把它们渲染为墙面纹理而不是独立物体。这种情况下自动标注无法生成它们的训练数据，只能依赖 CLIP 做开放词汇检测。

## 五、模块清单

| 文件 | 作用 |
|------|------|
| `src/perception/detector.py` | YOLO 检测器封装（多模型、NMS） |
| `src/perception/depth.py` | 距离估计（启发式 + Depth Anything） |
| `src/perception/pipeline.py` | 感知管道（检测→距离→可选 CLIP/先验） |
| `src/perception/verifier.py` | CLIP 检测结果验证与过滤 |
| `src/perception/prior.py` | 场景先验权重调整 |
| `src/perception/class_config.py` | YAML 类别配置加载 |
| `src/perception/finetune/collect.py` | 训练数据自动采集 |
| `src/perception/finetune/train.py` | YOLO 微调训练 |
| `src/perception/finetune/eval.py` | 检测质量评估（mAP/P/R） |
| `src/cli/perceive.py` | 感知交互 Demo（--check-classes, --verify-labels） |
| `config/classes.yaml` | 类别配置（80 COCO + 自定义类 + THOR 映射） |

## 六、使用说明

```bash
# 检查类别映射
python src/cli/perceive.py --check-classes --scene FloorPlan1

# 可视化验证标注效果
python src/cli/perceive.py --verify-labels --scene FloorPlan1

# 微调前评估（建立基线）
python src/perception/finetune/eval.py --model yolov8n.pt --num-scenes 5

# 采集训练数据
python src/perception/finetune/collect.py --scenes 10 --steps 200

# 微调训练
python src/perception/finetune/train.py --data data/data.yaml --epochs 50 --device cpu

# 微调后评估（对比提升）
python src/perception/finetune/eval.py --model runs/train/weights/best.pt --num-scenes 5

# 交互式感知 demo
python src/cli/perceive.py --model yolov8n.pt   # 预训练
python src/cli/perceive.py --model runs/train/weights/best.pt   # 微调后
```
