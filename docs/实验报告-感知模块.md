# 实验报告：Phase 2 — 视觉感知模块

**日期**: 2026-05-19 ~ 2026-05-25

---

## 一、阶段目标

在 Phase 1 搭建好场景控制和数据采集基础设施之后，这个阶段要完成机器人对室内环境的视觉感知能力。具体来说：

1. 用 YOLOv8 对 AI2-THOR 渲染画面做物体检测，输出物体名称、边界框、屏幕位置
2. 对检测到的物体估计距离——先给出具体米数，再映射到远近级别
3. 针对 YOLO 在仿真画面上检测效果差的问题，搭建微调工具链并执行微调
4. 将类别配置从硬编码改为 YAML 可配置，并修复重复类名
5. 用量化指标（mAP@0.5, Precision, Recall）评估检测质量，建立微调前后对比基线

## 二、模块设计

### 2.1 检测器 (`detector.py`)

`YOLODetector` 封装了 ultralytics 的 YOLO 模型。输入 RGB 图像，返回 `Detection` 列表，每条包含标签名、置信度、边界框和自动计算的屏幕位置（left/center/right）。

YOLO 的 COCO 80 类里没有 door、cabinet、lightswitch 等室内常见物体。这个限制通过可配置类别系统和微调来解决。

支持非极大值抑制（NMS）的 IoU 阈值调节，以及 5 种不同规模的预训练模型（yolov8n/s/m/l/x）。

### 2.2 距离估计 (`depth.py`)

两个策略共享 `DepthEstimator` 抽象接口，`estimate()` 返回 `(level, metres)` 二元组：

- **`HeuristicDepth`**：先通过针孔相机模型估算大致米数（`distance = assumed_size × focal_px / bbox_height_px`，默认假设物体高度 0.4m，FOV 90°），再用阈值映射到 NEAR（≤1.5m）、MEDIUM（1.5~3.0m）、FAR（≥3.0m）。不需要 GPU。
- **`DepthAnythingV2`**：单体深度估计模型，精度更高但需要 GPU 和额外依赖。失败时自动回退到 `HeuristicDepth`。

当 `PerceptionPipeline.process()` 传入 `controller` 参数时，距离会优先用 AI2-THOR 地面真值覆盖——通过 `ThorController.distance_to()` 查询场景中对应物体的精确 3D 坐标，计算 XZ 平面欧氏距离。保证了仿真环境内的距离精度。

### 2.3 CLIP 验证器 (`verifier.py`)

YOLO 的检测结果中包含假阳性。CLIP 验证器对每个检测框的裁剪区域计算文本-图像相似度（`clip_score`），作为第二层语义验证。提供 `filter_by_clip()` 按阈值过滤和 `rerank_by_clip()` 按 CLIP 分数重排两个工具函数。

不过 CLIP 在 CPU 上速度较慢（每帧几秒），目前作为可选增强功能。

### 2.4 场景先验 (`prior.py`)

根据 AI2-THOR 的 FloorPlan 名称判断房间类型（厨房/卧室/浴室/客厅，覆盖 FloorPlan1-30），对检测到的物体做置信度加权。例如厨房里 refrigerator 的置信度 ×1.3，bed 的置信度 ×0.5。只调权重不下结论，是否过滤留给下游决定。

在微调前效果有限——YOLO 本身检测太差，权重调整改变不了漏检。微调后可在边缘情况下辅助区分疑似类别。

### 2.5 类别配置系统 (`class_config.py` + `classes.yaml`)

这是解决 YOLO COCO 类别限制的关键设计。所有类别名和 AI2-THOR 物体类型到类别名的映射都在 `config/classes.yaml` 中定义。加新类只需编辑 YAML：

```yaml
names:
  - ... (原有 80 个 COCO 类)
  - door          # 加这里

thor_to_names:
  Door: door      # 加这里
```

不需要改任何 Python 代码。检测器、数据采集、评估三个下游模块从同一个配置加载，保证一致性。

**配置修复**：发现 names 列表中有 5 个重复类名（apple, fork, knife, spoon, vase 在 COCO 80 类中已存在，又在自定义类区域被追加了一次）。删除重复后 119 类 → 114 类，去除了 class_id 错配隐患。

辅助命令 `python src/cli/perceive.py --check-classes` 可加载场景，列出所有 AI2-THOR 物体，标注映射状态，直接给出需要添加到 YAML 的行。

### 2.6 数据采集与标注 (`finetune/collect.py`)

利用 AI2-THOR 的实例分割功能自动生成训练数据，完全不需要人工标注。原理：

1. 开启 `renderInstanceSegmentation` 后，AI2-THOR 返回一张颜色掩码图——每个可见物体一个独有颜色
2. 通过 `color_to_object_id` 映射查到物体类型
3. 通过 `classes.yaml` 映射到 YOLO class_id
4. 从掩码像素坐标算出边界框 → YOLO 格式的标签文件

机器人在场景中随机走动（MOVE_FORWARD / TURN / LOOK），自动采集帧和标签对。可视距离设为 10 米，避免默认 1.5 米只看到近处物体的问题。

**实际采集**：FloorPlan1-10，200 步/场景，共 1954 张标注帧。

### 2.7 评估模块 (`finetune/eval.py`)

评估流程分两步：先在 AI2-THOR 中自动生成验证集（默认训练集以外的 FloorPlan11-15，100 步/场景），再用 ultralytics 的 `model.val()` 计算 mAP@0.5、mAP@0.5:0.95、Precision、Recall。

评估时自动检测模型的类别数——预训练模型只评估 COCO 80 类（跳过自定义类），微调后模型评估全部 114 类。

输出包含整体指标和 per-class 表格，状态分四档：

- **GOOD**：AP≥0.6，可靠检测
- **OK**：AP≥0.3，可用，微调可提升
- **LOW**：AP>0，差
- **NONE**：AP=0，完全检测不到

**实际评估**：验证集 FloorPlan11-15，484 帧。微调前跑了一轮（`runs/detect/val/`），微调后跑了一轮（`runs/detect/val-2/`）。

### 2.8 可视化验证 (`--verify-labels`)

`python src/cli/perceive.py --verify-labels` 提供标注质量的可视化检查。机器人在场景中做 360° 环绕扫描→前进→再扫描的探索模式，每帧把 AI2-THOR 的 ground-truth 边界框和类别名画在图像上，保存到 `outputs/verify/`。运行结束后输出覆盖率报告，方便直观了解哪些物体在实例分割中有框、哪些没有。

### 2.9 感知管道 (`pipeline.py`)

`PerceptionPipeline` 将以上模块串联为 5 步流程：

```
RGB 图像
  → 1. YOLO 检测
  → 2. 场景先验加权（可选）
  → 3. CLIP 验证 + 过滤（可选）
  → 4. 距离估计（启发式 / 深度模型）
  → 5. AI2-THOR 真值距离覆盖（需传入 controller）
```

步骤 5 的设计要点：仿真环境中我们拥有地面真值，传入 controller 即可获得精确到厘米的距离，不传也能独立工作。

### 3.4 分析

**微调前**（mAP@0.5=0.027）几乎没有实用价值——YOLO 在真实照片上训练，面对 AI2-THOR 的 Unity 渲染画面（不同纹理、光照、材质）几乎完全不认得。这个数字比早期实验报告（mAP=0.146）更低，原因是 classes.yaml 扩展到 114 类后包含了 door、cabinet 等 COCO 完全无法检测的自定义类，拉低了整体平均。

**微调后**（mAP@0.5=0.672）模型已能较为可靠地检测 AI2-THOR 室内物体。box_loss 从 1.32 降至 0.72（边界框越来越准），cls_loss 从 5.06 降至 0.79（类别判断越来越准）。验证集指标在 epoch 40 后趋于平稳，训练可视为完成。

## 四、开发中遇到的问题

### 4.1 AI2-THOR 默认可视距离过短

`--verify-labels` 时大量物体没有标注框。排查发现 AI2-THOR 默认 `visibilityDistance=1.5m`，实例分割只渲染 1.5 米内的物体。室内场景通常 5-10 米见方，大部分物体在这个范围外。**修复**：验证和采集时可视距离设为 10 米。

### 4.2 YOLO 类别数与标注类别数不匹配

评估时遇到 `IndexError: index 83 is out of bounds for axis 1 with size 81`。原因是 `classes.yaml` 加了自定义类后总类别数超过预训练 YOLO 的 80 类，验证集标注包含 class_id>79 的标签。**修复**：验证集采集时自动检测模型类别数，过滤超出范围的标签。

### 4.3 AP 数组与类名索引对应错误

评估表格不输出数据，排查发现从 YOLO 的 `metrics.box.ap` 取值时按数组下标对应类名，但 YOLO 的 AP 数组只包含有 GT 标注的类，下标和 class_id 不一致。**修复**：用 `metrics.box.ap_class_index` 做正确的类名映射。

### 4.4 部分物体在实例分割中不可见

部分物体（Bottle、Fork、Lettuce 等）在验证阶段未被标注——它们在 AI2-THOR 中被放在柜子、抽屉里，物理上不可见。这不影响训练。Door、Window 等结构物件可能被渲染为墙面纹理而非独立物体，自动标注无法生成训练数据，只能依赖 CLIP 做开放词汇检测。

### 4.5 classes.yaml 重复类名

names 列表中 apple、fork、knife、spoon、vase 各出现两次——一次在 COCO 80 类区域，一次在自定义类区域。导致同一个名称对应两个 class_id，训练时标签分配会出错。**修复**：删除第二次出现的 5 个重复项，119 类 → 114 类。

### 4.6 训练输出路径嵌套

`train.py` 输出到了 `runs/detect/runs/train/` 而非预期的 `runs/train/`。原因是此前 `eval.py` 在 `runs/detect/` 下写了检测日志，ultralytics 内部基于当前目录做了路径拼接。**解决方案**：始终在项目根目录运行所有命令，微调后评估使用实际路径。

## 七、YOLO-World 开放词汇检测集成

### 7.1 动机

Phase 2 微调方案存在一个根本性问题：**每新增一个检测类别，都需要重新采集数据 → 重新微调 → 重新评估**。以当前 114 个类别的覆盖面，在 AI2-THOR 的 30 个 FloorPlan 场景中仍有大量物体无法被检测到（如 door、window、lightswitch 等结构物件，以及 FloorPlan 特有的稀有物体）。

YOLO-World (Cheng et al., CVPR 2024) [1] 将 YOLO 的实时检测能力与 CLIP 的开放词汇能力结合，通过 **"prompt-then-detect"** 策略实现零样本检测——用户只需提供类别名称列表，模型即可检测这些类别的物体，无需任何微调。

### 7.2 实现

新增 `YOLOWorldDetector` 类（`detector.py`），与 `YOLODetector` 保持相同的 `.detect(rgb) → list[Detection]` 接口：

- `set_classes(class_names)` — 动态设置检测词汇表，利用 CLIP 文本编码器生成类别嵌入
- `set_classes_from_config(classes_path, extra=...)` — 从 `classes.yaml` 自动加载全部类别，并支持追加额外目标（如 `door`, `window`）
- `create_detector(model_name, ...)` 工厂函数 — 根据模型名自动选择 `YOLODetector` 或 `YOLOWorldDetector`

支持 8 种预训练模型变体：`yolov8{s/m/l/x}-world{,-v2}.pt`，推荐 `yolov8s-worldv2.pt`（推理速度快，LVIS 零样本 mAP 约 22.0）。

### 7.3 CLI 使用

```bash
# 感知 Demo — YOLO-World 模式
python src/cli/perceive.py --yolo-world \
    --model yolov8s-worldv2.pt \
    --confidence 0.15 \
    --scene FloorPlan1

# 决策 Demo — YOLO-World 模式
python src/cli/decide.py --yolo-world \
    --model yolov8s-worldv2.pt \
    --task "Go to the refrigerator" --policy rule
```

### 7.4 Hybrid 混合检测器

逐帧 IoU 评估显示：微调 YOLO 在训练类上精度更高（0.681），但泛化差；YOLO-World 覆盖更广但假阳性多。两者的优势互补催生了 `HybridDetector`。

**合并策略**：同类 IoU 门控——微调 YOLO 做主检测，YOLO-World 补充未被训练的类别（door、window、mirror 等结构物件）。对于 YOLO-World 检出的同类物体，仅在与微调框 IoU≥0.5 时被抑制；不同位置的同名物体（如第二把椅子）保留。

### 7.5 任务级评估

逐帧 IoU 匹配过于严苛（GT 包含大量侧面/遮挡物体），改用任务成功率评估——测量 Agent 能否走到目标物体 1.5m 内。

```bash
python -m src.perception.eval_task --scenes FloorPlan1,FloorPlan3,FloorPlan5
```

**评估结果**（14 个导航任务 × 3 个场景）：

| 检测器 | 成功率 | 平均步数 | 平均耗时 |
|--------|--------|----------|----------|
| **Hybrid** | **78.6%** | 31.1 | 5.0s |
| YOLO-finetuned | 64.3% | 36.3 | 3.0s |
| YOLO-World | 42.9% | 57.9 | 7.1s |

Hybrid 比纯微调成功率高出 14 个百分点，同时少走 5 步。`decide.py` 已将其设为默认（`--detector hybrid`）。

### 7.6 三种检测器对比

| 维度 | Hybrid | 微调 YOLO | YOLO-World |
|------|--------|----------|------------|
| 任务成功率 | 78.6% | 64.3% | 42.9% |
| 新增类别 | 一行文本（自动补充） | 采集→训练（数小时） | 一行文本 |
| 假阳性控制 | 好（同类门控） | 最好 | 一般 |
| 适用场景 | **日常使用（默认）** | 固定场景高精度 | 快速原型 |

## 九、小结

Phase 2 感知模块完成。经历了三轮迭代：

1. **基础搭建**：YOLO 检测 + CLIP 验证 + 场景先验 + 距离估计 + 微调工具链
2. **代码优化**：配置缓存、per-class 物体尺寸（80+ 类）、置信度截断、死代码清理、CLIP 批量编码
3. **YOLO-World 集成 + Hybrid 方案**：零样本开放词汇检测 → 混合检测器 → 任务级评估

最终 Hybrid 方案以 **78.6% 任务成功率** 作为感知模块的交付状态，已设为 `decide.py` 默认检测模式。

## 参考文献

1. **Cheng, T., Song, L., Ge, Y., Liu, W., Wang, X., & Shan, Y.** (2024). *YOLO-World: Real-Time Open-Vocabulary Object Detection.* CVPR 2024. [arXiv:2401.17270](https://arxiv.org/abs/2401.17270) — YOLO-World 模型，本项目开放词汇检测的核心。

2. **Liu, S., Zeng, Z., Ren, T., Li, F., Zhang, H., Yang, J., Li, C., Yang, J., Su, H., Zhu, J., & Zhang, L.** (2024). *Grounding DINO: Marrying DINO with Grounded Pre-Training for Open-Set Object Detection.* ECCV 2024. [arXiv:2303.05499](https://arxiv.org/abs/2303.05499) — 另一种开放词汇检测方案，在机器人感知中表现优于 OWL-ViT [Manicka, 2024]。

3. **Radford, A., Kim, J.W., Hallacy, C., Ramesh, A., Goh, G., Agarwal, S., Sastry, G., Askell, A., Mishkin, P., Clark, J., Krueger, G., & Sutskever, I.** (2021). *Learning Transferable Visual Models From Natural Language Supervision.* ICML 2021. [arXiv:2103.00020](https://arxiv.org/abs/2103.00020) — CLIP 模型，本项目的验证器和 YOLO-World 的文本编码器均基于此工作。

4. **Yang, L., Kang, B., Huang, Z., Xu, X., Feng, J., & Zhao, H.** (2024). *Depth Anything V2: A More Capable Monocular Depth Estimation Model.* NeurIPS 2024. [arXiv:2406.09414](https://arxiv.org/abs/2406.09414) — 深度估计模型，本项目的 `DepthAnythingV2` 可选后端。若未来部署 GPU，可替代启发式距离估算。

5. **Shridhar, M., Thomason, J., Gordon, D., Bisk, Y., Han, W., Mottaghi, R., Zettlemoyer, L., & Fox, D.** (2020). *ALFRED: A Benchmark for Interpreting Grounded Instructions for Everyday Tasks.* CVPR 2020. [arXiv:1912.01734](https://arxiv.org/abs/1912.01734) — AI2-THOR 上的标准 embodied AI benchmark，本项目的任务设计与评估可参考其指标（SR, SPL）。

6. **Deitke, M., VanderBilt, E., Herrasti, A., Weihs, L., Salvador, J., Ehsani, K., Han, W., Kolve, E., Farhadi, A., Kembhavi, A., & Mottaghi, R.** (2022). *ProcTHOR: Large-Scale Embodied AI Using Procedural Generation.* NeurIPS 2022. [arXiv:2206.06994](https://arxiv.org/abs/2206.06994) — 大规模程序化 THOR 场景生成，为后续扩展训练数据规模提供了方法参考。

7. **Chhipa, P.C., Chippa, V., Shrivastava, A., Liwicki, M., & Saini, R.** (2024). *Open-Vocabulary Object Detectors: Robustness Challenges under Distribution Shifts.* ECCV 2024 Workshop. [arXiv:2405.14874](https://arxiv.org/abs/2405.14874) — 评估了 Grounding DINO、YOLO-World、OWL-ViT 在分布偏移下的鲁棒性，对 sim-to-real 迁移有直接参考价值。
